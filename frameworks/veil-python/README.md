# veil-python

An application written with [veil-api](https://pypi.org/project/veil-api/), the Python bindings of the
[veil](https://github.com/aofusa/veil-proxy) server. The HTTP/1.1, HTTP/2, HTTP/3 and WebSocket server is veil's
(Rust); Python runs the handlers. The Linux wheels use veil's epoll readiness reactor.

## Endpoints

| Endpoint | Implementation |
|---|---|
| `GET`/`POST /baseline11`, `GET /baseline2`, `GET /pipeline` | `@app.get` / `@app.post` with `a: int, b: int` bound from the query; `offload=False` runs these small, non-blocking handlers on the network worker (documented in veil-api's production notes) |
| `GET /json/{count}?m=` | returns a `dict`, serialized to JSON by veil on every request |
| `GET /delay/{ms}` | `async def` with `await asyncio.sleep`, on veil's persistent asyncio event loop |
| `POST /echo` | returns the request body |
| `GET /ws` | `@app.websocket`, echoing text and binary messages |
| `benchmark.BenchmarkService` (gRPC) | the servicer generated by `grpcio-tools`, added to `veil.grpc.Server(app)` with the generated `add_BenchmarkServiceServicer_to_server` |
| `/static/*` | `app.serve_dir` (veil's File backend: br/gzip compressed on the fly on HTTP/1.1, HTTP/2 and HTTP/3, uncompressed responses with sendfile on HTTP/1.1, caches that follow the disk) |

## Configuration

`veil.toml` holds the settings of veil-api's production guide: JSON application log, no access log, OpenAPI off,
response compression on (`[api] compression`), static caches following the disk. The four HttpArena listeners are
`[[listener]]` entries in **one process**.

## Completeness

- routing, request, response: decorators with path parameters; query, header and body binding (buffered, or a
  stream with `stream_body=True`); `dict` / `str` / `bytes` / `veil.Response` / streaming and file responses.
- middleware: declared `false`. veil-api has dependencies (`Depends`, run before the handler and able to answer
  early) and native CORS, but no general before-and-after middleware around native routes.
